SENTIA · PHP + MYSQL NO XAMPP

O QUE USA O BANCO
Os registros educativos de "Meu registro", no site principal, podem ser salvos,
consultados, editados, marcados como concluídos e apagados no MySQL.
O Jardim dos Ecos mantém seu save local. Ele não usa esta tabela.
HTML, CSS e JavaScript continuam em arquivos separados. O PHP fica somente em api/.
O site deve ser aberto pelo Apache para executar PHP; file:// e Live Server não
executam essa API. O site continua explicando a indisponibilidade se o PHP/MySQL
não estiver pronto.

COMO ABRIR
1. Instale/abra o XAMPP e inicie Apache e MySQL no painel.
2. Coloque a pasta completa Sentia dentro da pasta htdocs do XAMPP.
   Exemplo comum: C:\xampp\htdocs\Sentia\index.html
   Mantenha api, banco, assets, css e js junto dos HTMLs.
3. Acesse http://localhost/Sentia/ no navegador.
   Se o Apache usa outra porta, inclua essa porta, por exemplo :8080.
4. No site, use "Preparar banco" quando essa opção aparecer. O botão faz um
   POST explícito para api/instalar.php. Só esse pedido cria banco e tabela.
   Abrir status.php ou instalar.php pelo endereço não altera o MySQL.
5. Alternativa sem o botão: abra http://localhost/phpmyadmin, vá em Importar,
   escolha banco/schema.sql e execute a importação. O SQL cria sentia/registros.
6. Confira http://localhost/Sentia/api/status.php:
   quando pronto, responde ok:true, ready:true e recordsCount.

CONFIGURAÇÃO PADRÃO
Servidor: 127.0.0.1
Porta MySQL: 3306
Banco: sentia
Usuário padrão local do XAMPP: root
Senha padrão local do XAMPP: vazia
Conexão: PDO MySQL, charset utf8mb4, consultas com parâmetros preparados.

Se os dados do seu MySQL forem diferentes, copie api/config.local.example.php
para api/config.local.php e ajuste host, port, database, username e password.
O arquivo config.local.php é lido pelo PHP e nunca precisa ir para o JavaScript.
Não publique um config.local.php que contenha sua senha pessoal.
Também é possível usar variáveis de ambiente no Apache: SENTIA_DB_HOST,
SENTIA_DB_PORT, SENTIA_DB_NAME, SENTIA_DB_USER e SENTIA_DB_PASSWORD.
A configuração local, se existir, tem preferência sobre os padrões/variáveis.
Se trocar o nome do banco, o botão Preparar banco usa o novo nome configurado;
o arquivo SQL de importação manual usa o nome sentia até você alterá-lo.

O botão de instalação só aceita POST vindo do próprio computador do XAMPP
(127.0.0.1/::1). Para jogar pelo celular na rede, prepare primeiro no computador.
Importar ou instalar novamente não executa DROP, TRUNCATE nem limpeza de dados.
O usuário do MySQL precisa poder criar banco/tabela na instalação; depois disso,
a API de registros usa SELECT, INSERT, UPDATE e DELETE.

TABELA
registros:
  id          VARCHAR(64) PRIMARY KEY, identificador sensível a maiúsculas
  text        VARCHAR(160), texto da ação em UTF-8 (até 160 caracteres Unicode)
  done        TINYINT(1), devolvido ao navegador como booleano true/false
  created_at  TIMESTAMP, criado pelo MySQL
  updated_at  TIMESTAMP, atualizado automaticamente pelo MySQL

Esta versão escolar não tem contas/login. Os registros do MySQL são uma lista
compartilhada por quem acessa a mesma instalação do SENTIA. O navegador não manda
o save, as escolhas ou os dados narrativos do Jardim para a API.

CONTRATO DA API (JSON)
Os endereços são relativos à pasta do projeto; não dependem de domínio fixo.
Requisições que enviam dados usam Content-Type: application/json.

GET api/status.php
200: {"ok":true,"ready":true,"database":"sentia","recordsCount":0}
503: {"ok":false,"ready":false,"error":{"code":"schema_missing",
       "message":"Explicação para preparar o banco."}}
Outros códigos de indisponibilidade: database_unavailable, php_mysql_missing.

GET api/registros.php
200: {"ok":true,"registros":[{"id":"abc123","text":"Fazer uma pausa","done":false}]}
A lista vem ordenada por created_at e id. Datas são internas ao banco.

POST api/registros.php
Corpo: {"id":"abc123","text":"Fazer uma pausa","done":false}
id é opcional; se ausente, o PHP cria um identificador de 32 caracteres.
done é opcional e seu padrão é false.
201: {"ok":true,"registro":{"id":"abc123","text":"Fazer uma pausa","done":false}}
Identificador repetido: 409 id_exists; não sobrescreve o registro existente.

PUT api/registros.php
Corpo: {"id":"abc123","text":"Caminhar um pouco","done":true}
id é obrigatório. Envie text, done ou os dois. Os campos omitidos são preservados.
200: {"ok":true,"registro":{"id":"abc123","text":"Caminhar um pouco","done":true}}
Registro ausente: 404 not_found. Salvar valores iguais continua sendo sucesso.

DELETE api/registros.php
Corpo: {"id":"abc123"}
200: {"ok":true,"deleted":1}
Se já tiver sido apagado, deleted é 0 (a operação continua sendo sucesso).
Para limpar a lista toda explicitamente: corpo {"all":true}.
Nenhum GET apaga dados. DELETE sem id nem all:true é rejeitado.

GET api/instalar.php
200: explicação JSON com requiresPost:true. Não cria banco nem tabela.
Use status.php para consultar o estado real.
POST api/instalar.php
Não precisa enviar corpo. Cria banco/tabela se ausentes e preserva o que existe.
200: {"ok":true,"ready":true,"database":"sentia","message":"Banco preparado..."}

ERROS E VALIDAÇÃO
Formato comum: {"ok":false,"error":{"code":"...","message":"..."}}
400 JSON inválido; 405 método não aceito; 413 corpo acima de 8 KiB;
415 Content-Type incorreto; 422 campo/tipo/tamanho inválido; 503 MySQL indisponível.
id aceita de 1 a 64 letras ASCII, números, traços ou sublinhados.
text precisa ser string não vazia, até 160 caracteres Unicode, sem controles.
done precisa ser booleano JSON, não string "true" ou número 1.
Campos desconhecidos são rejeitados. HTML digitado não é executado pelo site;
o front-end deve continuar exibindo o texto com textContent.
Falhas retornam mensagens úteis sem expor consultas, caminhos, usuário ou senha.

SE NÃO FUNCIONAR
- Página mostra código PHP como texto: você abriu fora do Apache ou o PHP não
  está habilitado. Use http://localhost/Sentia/, nunca abra o PHP como arquivo.
- database_unavailable: inicie MySQL e confira porta/usuário/senha locais.
- schema_missing: prepare o banco ou importe banco/schema.sql.
- php_mysql_missing: ative extension=pdo_mysql no php.ini do XAMPP e reinicie Apache.
- Apache não inicia: confira no painel XAMPP se outra aplicação usa a mesma porta.
- No celular, localhost significa o próprio celular. Use o IP do computador e a
  porta do Apache, estando ambos na mesma rede. Prepare o banco no computador.

VALIDAÇÃO
Se o PHP estiver disponível, verifique sintaxe com php -l em cada arquivo api/*.php.
Com Apache/MySQL prontos, teste a criação, consulta, edição, conclusão e exclusão
de uma ação pela página Meu registro e veja a tabela no phpMyAdmin.

A API foi conferida em PHP 8.4.27 com PDO MySQL e MariaDB 11.4.12 numa instância
temporária separada, sem alterar um banco pessoal. Passaram CRUD, instalação
repetida preservando registros, identificadores duplicados, 160 emojis Unicode,
edição parcial, exclusão repetida e rejeição de 19 pedidos inválidos.
Também foram conferidos método incorreto, Content-Type incorreto, JSON/UTF-8
inválidos e respostas distintas para extensão ausente, servidor parado e banco
ainda não preparado. O relatório fica em documentacao/TESTE-API-XAMPP.json.
